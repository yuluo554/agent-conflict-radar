# agent-conflict-radar 技术报告

> 本文说明**四件事的口径**：worktree / 会话归集、`git merge-tree` 试合并的边界、AST 符号区间
> 比对方法、严重度分级与隐私设计；并把"这些口径如何被**可复跑的证据**钉住"逐条落到命令与测试名上。
>
> **数值不在本文复制**：所有阈值只有一个来源 `config/radar.toml`（K3）。本文只写**键名**，
> 要看生效值请跑 `radar config`（输出含 `source_path`）。

---

## 一、问题与判据

多个编码 agent 并行改同一个仓库时，冲突在**合并那一刻**才暴露。此时一个 agent 已覆盖了另一个的工作，
返工成本已经发生。本工具把冲突的发现点前移到**写入发生时**：

| 粒度 | 判据（一句话） | 产物字段 |
|---|---|---|
| 会话 / 工作区级 | 哪些 agent 会话**活跃**、各自在哪个 worktree / 分支 | `active_cells`、`derived_from` |
| 文件级 | 同一 `path` 出现在两个不同且活跃的 `(workspace, session)` 组里 | `levels` 含 `file` |
| 区块级 | 两条分支做**无副作用试合并**，冲突路径含本 `path` | `levels` 含 `block` |
| 符号级 | `HEAD` 版本的 AST 里，两侧改动落在**同一符号**或**相邻符号** | `levels` 含 `symbol`、`symbols` |

**一条记录 = 一个 `(workspace_a, workspace_b, path)` 组合**；`levels` 是命中的粒度**集合**，
`level` 是其中最高的一档（**只用于排序与严重度，不用于匹配**）；`symbols` 是命中的符号限定名集合。
真值按 `levels` / `symbols` **集合精确匹配**——多报、漏报**都计失败**。

`degraded` / `approximate` 只降粒度、**不改判定、不改退出码**，但都落进 `undetermined`
（原因码 `degraded` / `symbol_unavailable` / `unsupported_format`）逐条列出。
**"没底"绝不写成"没问题"**——这是判定类工具的正确性底线。

## 二、worktree / 会话归集口径

### 2.1 输入

* **worktree 枚举**：`git worktree list --porcelain`（只读白名单内的子命令）；
* **会话日志**（两种 harness 的**实测形态**，见 `data/README.md` §六）：

| 源 | 形态 | 关键字段 |
|---|---|---|
| Claude Code | JSONL，**首行不是消息行**（多为 `last-prompt`） | `cwd` / `gitBranch` / `timestamp` / `message.content[]` 里的工具调用 |
| Codex | JSONL，首行恒为 `session_meta` | `payload.cwd` / `payload.id` / `payload.session_id`（**子会话没有**）/ `parent_thread_id` |

### 2.2 归集规则

1. **会话 → 工作区**：会话声明的 `cwd` 与该会话工作区路径比对；匹配不到任何 worktree 的会话
   仍在表里登记（`cells_outside_worktree`），但它的写操作**不参与**冲突判定。
2. **活跃判定**：`window.active_minutes` 之内有过写操作 → 活跃；参考时刻 `--now` 显式传入时
   以它为准（**不读系统时钟**，否则同一输入两次运行会得到不同判定）。`window.scan_days` 决定
   扫描面（窗口外的会话一律不进活跃表）。
3. **subagent 判定**：Codex 子会话靠 `parent_thread_id` 认父（子会话**没有** `session_id`，
   这是实测形态，不是假设）；父会话缺失时落 `undetermined(parent_not_found)`，**不猜**。
4. **`derived_from` 去重**：两侧 `derived_from` 相同（同一 parent 派生的 subagent）→
   **默认不产出该对**，并在 `counts.derived_sibling_pairs_skipped` + 一条 note 里**留痕**。
   "悄悄少一条"与"去重"在产物上必须可区分。

### 2.3 降级与"看不懂"要分开

| 现象 | 处置 | 原因码 |
|---|---|---|
| 未知的会话格式版本 | 不解析该文件 | `unsupported_format` |
| 单行超过 `scan.max_line_bytes` | **显式报错**、不静默截断 | `line_too_long` |
| 只有元信息、没有消息行 | 不进活跃表 | `no_message_line` |
| 父会话缺失（Codex 子会话） | 不推断父子关系 | `parent_not_found` |

这些都不改变退出码：`scan` 成功**恒为 0**。

## 三、`git merge-tree` 试合并的边界

区块级检测用 `git merge-tree --write-tree <branch_a> <branch_b>`——它**只在对象库里写临时
tree/blob**，不改索引、不改工作区、不建分支、不动 HEAD。这是本工具"只读"的边界，
`README` 与产物 `notes` 都如实披露。

实测形态（git `2.54.0.windows.1`，见 `data/README.md` §6.1）：

| 形态 | 退出码 | 处置 |
|---|---|---|
| 无冲突 | 0 | 不报 `block` |
| 真冲突 | 1 | stdout 有**三元组行** + `CONFLICT` 文案；两条来源都认（只认一条会漏 `modify/delete`） |
| 无共同祖先 / 非 git 目录 | 128 | **降级** `degraded=true` + `undetermined(degraded)`，**不读成"无冲突"** |
| 超时 | —— | exit 3（环境问题），不静默降级 |

两条实测结论值得单独写出来：

1. **同文件不同函数、同函数内相隔数行的改动，git 会自己合并（exit 0）**——这正是符号级
   检测的价值窗口：文件级与区块级都看不见的地方，符号级能看见。
2. **两侧分支必须属于同一仓库**：判据用 `git rev-parse --git-common-dir` 比对，
   **不用路径前缀**（worktree 算同一仓库，路径前缀判会错）。

## 四、AST 符号区间比对方法

### 4.1 取符号

对 `HEAD` 版本（**不读工作区文件**）的 Python 源文件做 `ast.parse`，取顶层
`FunctionDef` / `AsyncFunctionDef` / `ClassDef` 的**限定名**与 `(lineno, end_lineno)`。
嵌套定义产生 `A.B.f` 形态的限定名——**按限定名匹配**，同名不同作用域不同键。

### 4.2 三种关系

设两侧改动区间为 `L` / `R`，符号区间表为 `S`：

| 关系 | 判据 | 报什么 |
|---|---|---|
| 同一符号 | `touching(L) ∩ touching(R) ≠ ∅` | 交集的**最内层**符号（`A` 与 `A.f` 同时命中只报 `A.f`） |
| 相邻符号 | 各自落在某符号**内部**，且 `range_gap(L, R) <= symbol.adjacent_tolerance` | 各自的最内层符号 |
| 其它 | —— | **不升格**（维持文件级） |

`range_gap` 是两侧区间之间的行数间隔；`<=` 是刻意的语义——矩阵里 `threshold_exact`
（间距 == 容差）**必须命中**，`threshold_near_miss`（间距 == 容差 + 1）**必须不命中**。
这两条**成对**卡在阈值两侧；只测"该命中"的那一侧，阈值写错永远不会红。

### 4.3 什么时候不做符号级（`approximate=true`）

* 非 `.py` 文件（R4 口径：未闭环的能力**不宣称**）；
* 取不到 `HEAD` 版本 / AST 解析失败；
* 两侧跨工作区（行号不可比）。

此时产物里**不出现任何符号字段**（连空数组都不出现）：报一个空集合会被读成"没有符号命中"，
而那是我们**给不出**的结论。

### 4.4 意图侧（`radar intent`）

符号级的上游是"谁改了哪一段"。三分法把"定位到什么程度"显式化：

| 落点 | 判据 | 形态 |
|---|---|---|
| `exact` | 磁盘 `git diff -U0` 的 hunk，或会话锚点在 `HEAD` 基线里**唯一命中** | `changed_ranges` 非空 |
| `coarse` | 文件定位到了但区间不可精确断言（`replace_all` / 锚点 0 处或多处命中 / 内容未变 / 删除 / 非 git 工作区） | `changed_ranges` 为空 |
| `unknown` | 连文件都定不下来（`MultiEdit`、缺 `file_path`、patch 无文件指令行） | `path == ""` + 按**写操作条数**计数 |

三条纪律：锚点多处命中必须点名命中次数（`anchor_ambiguous#2`），**绝不挑第一个**；
磁盘是事实（会话与磁盘不一致时以磁盘为准 + `disk_and_session_disagree`）；
计数两个口径分开登记（`exact+coarse+unknown == entries` 是**集合划分**；
`unknown_write_ops` 是**写操作条数**）。

## 五、严重度分级口径

严重度**只用于排序与展示分级**，不参与"是否有冲突"的判定，也不改变退出码。
档位按固定顺序选（`[severity]` 的四个权重键）：

| 档位键 | 触发条件 |
|---|---|
| `same_symbol` | 同一符号被两侧修改 |
| `same_file_diff_symbol` | 同文件不同符号（或区块级命中） |
| `adjacent_lines` | 符号级命中来自"相邻"关系 |
| `file_only` | 仅文件级同改 |

报告里的**建议文案是规则模板**：按 `severity_key` 分派固定句子，不是模型判断；
时间一律呈现原值，**不编造**"预计完成时间"。报告顶部常驻一句声明：本工具是辅助参考，
不合并、不解决冲突、不接管编排。

计数的**两栏**（K12）必须在报告里分开呈现：

* `by_max_level` 是**划分**（按最高粒度归类，`sum == len(conflicts)`）；
* `by_level_membership` 是**成员数**（一条记录可同时命中多级，可大于条目数）。

## 六、隐私设计

四层，每层都有可复跑的落点：

1. **接口面**：只用标准库；`tools/verify_offline.py` 的导入面审计扫源码，出现
   `socket` / `urllib` / `requests` 等即红。零第三方运行时依赖是"断网可跑"的结构性前提，
   不是偏好。
2. **数据面**：会话日志含 prompt 与代码，检测链路**只抽结构化字段**（`cwd` / 分支 / 时间戳 /
   文件路径 / 改动片段），**不落 prompt 正文**；证据只记 `文件:行号`。
3. **入库面**：真实日志、真实路径清单、真实 session id 一律不进仓库。`bench/` 下只有生成器
   同步产出的**白名单假值**（假 session id `sess-radar-NNNN`、假用户名 `radar-user`、
   固定基准时间 `2026-01-01T00:00:00Z`）。`tests/test_bench_matrix.py` 与
   `tests/test_intent.py` 断言零真实值命中；生成器 `--check` 断言冻结产物里**没有本机绝对路径**。
4. **运行面**：不给 `--out-dir` 时零写盘（`scan` / `intent` / `detect` / `report` 都有
   "CWD 里一个文件都不落"的断言）。`bench` 是唯一默认写盘的命令——它的 `last_run.json`
   本身就是交付物，落在矩阵目录而非用户目录，且**不含本机路径**（`{{WORK}}` / `{{BENCH}}`
   占位符替换）。

**"自动发现本机数据"的参数一律两侧显式传**：`scan` / `intent` / `detect` / `report` / 测试 /
冒烟全部显式给 `--claude-root` / `--codex-root`。缺省探测会真的去读用户本机日志（本机实测：
漏传一侧即读进 125 个真实会话文件）。

## 七、基准与可复现性（M5）

### 7.1 两棵树

| 树 | 内容 | 真值语义 |
|---|---|---|
| `bench/scenarios/` | 冲突矩阵 7 条 | `levels_expected` / `symbols_expected` / `objects_expected` / `objects_forbidden` / `geometry` / `git_expected_merge_exit` |
| `bench/intents/` | 意图矩阵 8 条 | `entries_expected` / `unknown_expected` / `counts_expected` / `geometry` |

两棵树**分开冻结**：M1 的冲突真值判据是"每条场景恰好两个改动侧 + 符号区间落在基线内"，
而意图真值要覆盖 `MultiEdit`（连文件都没有）与缺 `file_path`——合进一棵树就要**放宽判据**，
那是"改松门禁换便利"。

### 7.2 评分的判据（`radar bench`）

1. 逐场景**物化**成真 git 仓库 + 真会话日志（不是读一份静态期望）；
2. 跑 `scan → intent → detect` **完整链路**；
3. 与真值做**集合精确匹配**：`missing`（漏报）/ `extra`（多报）都非空即失败；
4. 反向样例单独成项（`objects_forbidden` / `paths_forbidden` / `levels_forbidden`）；
5. 覆盖度门槛在**消费侧**再验一遍（`min_count_by_type` / `missing_types` / 真值 sha256）——
   只信生成器的话，"台账被手改但生成器看不出"会照常给出 PASS；
6. 结果落 `last_run.json`（冻结序列化契约 + 机器无关 + 双跑逐字节一致）；`--only` 抽检
   **不覆盖**矩阵目录里的整矩阵记录（抽检要落盘须显式给 `--out-dir`）。

**可证伪探活打在消费处**：把某条真值的期望改一位 → `run_bench()` 必须报未达标。
变异组 M35 把评分函数里的 `missing` 恒置空，这条探活当场变红——证明"评分真的在比对"，
而不是只遍历真值打印 PASS。

### 7.3 冻结纪律

| 纪律 | 落点 |
|---|---|
| 确定性 RNG（禁 stdlib `random`） | `bench/rng.py` |
| 禁系统时钟 | 产物无时间戳；会话时间戳 = 固定基准 + 确定偏移；评分参考时刻是模块常量 |
| 禁 set 迭代序 | 遍历前一律排序 |
| 提交可复现 | 固定 `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE` / 作者；`--check` 复算提交 sha |
| `.git` 不入冻结产物 | 内部字节随 zlib/git 版本漂，跨平台不可能逐字节重现 |
| 两层 `--check` | ① 冻结产物形态；② 重跑生成器到临时目录逐字节比对 |
| 生成侧 / 生产侧规范序各一份 | 一致性靠**逐字节测试**断言，不靠共用实现 |
| 阈值符号引用 | 真值里写 `config:symbol.adjacent_tolerance`，`--check` 现场求值 |

## 九、已知边界与如实披露

1. **本机真实并行冲突样本几乎为零**：同文件重叠 **0 对**（详见 `data/README.md`）。
   因此本文与 README 的所有检出率/准确率口径**都来自合成基准**，不用真实样本数包装准确率。
2. **符号级不是首创**：`amaar-mc/wit` 的 README 已口头占位同方向。本项目的差异化只押
   "会话进行中的实时符号区间比对 + worktree 拓扑 + 可复现冲突矩阵**三者同时覆盖**"。
3. **两个未消费 / 未落地的键**：
   * `symbol.min_overlap_lines` —— **遗留键**：判定规则是"同一符号 ∪ 间距 ≤ 容差"，
     行区间重叠行数只是**展示**口径，不参与判定。保留它是为了键空间稳定（K3 改名要五处同步）；
     报告"参数来源"块仍列出键名，但它**不是判定阈值**。M5 不改判定规则（引入第二套规则会让
     "真值可独立复算"分叉）。
   * `derived_from` 的"提示开关" —— 配置里**没有**这个键，默认行为是"不产出 + 留痕"。
     加键属于数值口径变更，需五处同步，本轮不做。
4. **`merge-tree` 的 `--write-tree` 会在对象库写临时对象**：这是唯一被披露的写行为，
   已写进产物 `notes` 与 README。
5. **Windows 没有零依赖桌面通知通道**：`report.notify=true` 的真实结果是
   `notify_unavailable`（如实登记，不是缺陷）。
6. **评分耗时**：整矩阵约 20 秒（15 条场景各自物化一个真 git 仓库）。冒烟只跑子集，
   全量留给 CI 的独立步骤。
7. **CI 未接远端实跑**：本地按同一条命令复跑过；"四腿全绿"需要首推后由 CI 给出。

## 十、怎么自己复核
