## M1 工作区与会话发现

**模块**：`src/agent_conflict_radar/discover.py`（+ `gitio.py` / `versions.py`）
**交付命令**：`radar scan --repo <path> [--claude-root P] [--codex-root P] [--window D] [--out-dir D] [--now ISO8601]`（M1 已交付）

> **M1 落地勘误（2026-10-17，实测后追加；原措辞保留）**：
> ① `--now` 是**子命令选项**（在 `add_repo_options` 里统一注册），不是"全局选项"——它与 `--window`
> 一起出现在 `scan` 的用法里，读者不必记住"哪个旗标要写在子命令之前"。确定性测试与基准**必须显式传**。
> ② 交付态实测：`radar scan` 成功**恒为 0**（`undetermined` 只提示、不改码）；`--repo` 不在 git 仓库内
> 也是 exit 3（而不是"空表 + exit 0"）。③ 步骤 3 的"读首行 JSON"已被 M1 实测推翻（见下方勘误注）。

### 输入

| 来源 | 取法 | 备注 |
|---|---|---|
| worktree 集合 | `git worktree list --porcelain` | 主工作区 + 各 worktree 的路径/HEAD/分支；**按行解析**，路径可含空格 |
| Claude 会话 | `<claude-root>/**/*.jsonl` | 逐行 JSON；抽 `cwd` / `gitBranch` / 时间戳 / parent 关系 |
| Codex 会话 | `<codex-root>/**/*.jsonl` | 逐行 JSON；抽会话元信息中的工作目录 / 时间戳 |
| 显式覆盖 | `--repo` / `--claude-root` / `--codex-root` / `--window` / 环境变量 | 路径自适应，**不硬编码用户名** |

### 处理（六步）

1. **worktree 解析**：逐行状态机读 `--porcelain`（`worktree <path>` / `HEAD <sha>` / `branch <ref>` / `bare` / `detached`），产出 `Worktree[]`，主工作区置 `is_main=True`。
2. **会话文件发现**：从 root 递归收集 `*.jsonl`；root 不可读/不存在 → **显式报错**（`SourceNotFound`，exit 3），不得返回空表。
3. **归属判别（按文件形态，不按目录名）**：读首行 JSON →
   - 顶层含 `message` → Claude 解析器；
   - 顶层含 `payload`（或 `session_meta.payload`）→ Codex 解析器；
   - 两者都不含 → `unsupported_format`，记入 `undetermined` 并**点名文件**。
   > **⚠️ M1 勘误（本条措辞保留，但判据已修正）**：**不能只看首行**。实测 Claude 首行
   > `type` 为 `last-prompt`(58) / `queue-operation`(36) / `user`(28) / `started`(3)——首行常常不是消息行。
   > 实现改为"向下找**第一条带判别键**的行"，并把该行的**源行号**作为 `seq`。
   > `tests/test_discover.py::test_claude_first_line_is_not_message_line_and_seq_is_source_line_number`
   > 与 `test_bench_matrix.py::test_sessions_carry_the_measured_harness_shapes` 从两侧钉住这条。
4. **字段抽取 + 版本指纹**：对每个文件求字段指纹 → 与 `versions.py` 的**显式集合**比对：
   - 命中 → 按该版本规范抽取；
   - 未命中 → `unsupported_format`，**列出缺失键**（键名来自该版本的必需键列表），该文件整体不入表并计数。
5. **派生关系**：识别 parent/child（子会话指向父会话 id）→ 子会话 `derived_from=<parent id>`；独立会话为 `None`。
   > **⚠️ M1 落地修正**：`session_key = "<source>:<相对会话根的 posix 路径>"` 才是唯一键（`sessionId` 不够用：
   > Claude 主/子文件共享同一 `sessionId`，Codex 子会话干脆没有 `session_id`），故 `derived_from` 指向
   > **父会话的 `session_key`**，不是 `sessionId`。
6. **活跃 cell 组装**：按"工作区路径 ↔ 会话 `cwd`"匹配（路径规范化：`expanduser` + 词法归一，**不 resolve 符号链接**——resolve 会把符号链接形态的 worktree 路径改写掉，导致匹配失效）；对每个 `(session, workspace)` 求活跃窗（最后一次写操作 + 活跃窗长，窗长读 config）→ `ActiveCell[]`。

### 输出

`radar scan` 向 stdout 打印（或 `--out-dir` 落 `scan.json`）`WorkspaceTable`：

```json
{"reference_time":"2026-01-01T00:10:00Z",
 "worktrees":[{"path":"…","head":"…","branch":"…","is_main":true}],
 "sessions":[{"source":"claude","session_key":"claude:sess-a.jsonl","session_id":"sess-radar-0001",
              "cwd":"…","git_branch":"feat/agent-a",
              "start_ts":"2026-01-01T00:00:00Z","end_ts":"2026-01-01T00:09:00Z",
              "is_subagent":false,"derived_from":null,"file":"sess-a.jsonl","seq":3}],
 "active_cells":[{"workspace":"…","source":"claude","session_key":"claude:sess-a.jsonl",
                  "session_id":"sess-radar-0001","window_start":"…","window_end":"…",
                  "is_subagent":false,"derived_from":null,"in_worktree":true}],
 "undetermined":[{"file":"…","source":"claude","code":"no_message_line","detail":"…"}],
 "notes":["…"],
 "counts":{"worktrees":1,"sessions":2,"active_cells":2,"undetermined":0,
           "subagent_sessions":0,"cells_outside_worktree":0}}
```

**字段口径（M1 实测后定稿，动了会打挂基准）**：

| 字段 | 口径 |
|---|---|
| `session_key` | `"<source>:<相对会话根的 posix 路径>"`。**不能用 `sessionId` 做唯一键**：实测 Claude 主/子文件共享同一 `sessionId`，Codex 子会话没有 `session_id` |
| `derived_from` | 父会话的 `session_key`；解析不到父会话 → `null` + `undetermined(parent_not_found)` |
| `is_subagent` | Claude：`isSidechain` 为真；Codex：有 `parent_thread_id` |
| `seq` | 会话元信息所在行的**源文件行号**（Claude = 第一条消息行，Codex = 首行 `session_meta`），不是数组下标 |
| `in_worktree` | 该 cell 的 `cwd` 是否匹配到已知 worktree（精确或最长前缀）。匹配不上时保留原始 `cwd` 并置 `false`——**不丢弃、也不假装属于某工作区** |
| `reference_time` | 活跃判定的参考时刻：`--now` 显式传；缺省取观测到的最大会话时间戳（输入的函数，保双跑一致） |
| `undetermined[].code` | 稳定原因码：`unsupported_format` / `no_message_line` / `missing_cwd` / `parent_not_found` / `line_too_long` / `worktree_list_failed` |

### 算法要点

- **归属判别按行的结构形态，不按目录名，且不能只看首行**（M1 实测：Claude 首行 58/125 是
  `last-prompt`、36 是 `queue-operation`，都不是消息行）→ 向下找第一条带判别键的行。
- **`seq` 必须是源文件行号**（1-based），不是数组下标——行号可由日志复算，下标会随过滤漂移。
- **排序键**：`sessions` 按 `(source, session_id, file, seq)`；`worktrees` 按 `(is_main desc, path)`；
  `active_cells` 按 `(workspace, source, session_id, session_key)`；`undetermined` 按 `(source, file, code)`。
  全部可从输入复算。
- **subagent 去重**：同一 `derived_from` 的子会话与父会话**不构成跨 agent 并行**；M1 只标注，M3 据此过滤。
- **行长上限**：`scan.max_line_bytes`（读 config）超限即 `EnvironmentError_`，该文件落
  `undetermined(line_too_long)`——**不静默截断**。

### 确定性纪律

- 同一输入 → 同一排序、同一 cell 集合；`radar scan` 双跑输出**逐字节一致**。
- 全程**不读时钟**：时间戳一律取会话/文件原值。
- 找不到会话源 → 显式报错 exit 3，**不得伪造空结果、不得退化为 exit 0**。
- 未识别格式**不静默**：`undetermined` 独立分区 + 点名文件 + `missing_keys`。

### 降级与退役

- Claude `MultiEdit` / Codex `apply_patch` 字段形态为 ✅ R2/R3 **已闭环**（M1 实测）：`apply_patch` 的
  `input` 是**字符串**（以 `*** Begin Patch` 开头，含 `*** Update File:` 等指令行）；`MultiEdit` 本机
  **0 次出现** → 按"不编造"纪律，M2 遇到它一律落 `unknown` + 计注记，**不假装支持**。
- **非 git 仓库**：`--repo` 不在 git 仓库内 → exit 3（worktree 枚举与试合并都依赖 git），
  **不退化成空表 exit 0**。会话 `cwd` 落在任何 worktree 之外是**正常情形**（本机 37 个改文件的会话里
  只有 7 个在 git 仓库内）：这类 cell 保留原始 `cwd` 并置 `in_worktree=false`，不丢弃也不假装归属。
- **超长行**：`scan.max_line_bytes` 超限 → `undetermined(line_too_long)`，**不静默截断**。
- M1 交付后，`scan` 在"阶段未就绪表"中的 exit 4 断言**已整项退役**（K1 四步：`stages.py` 挪表 →
  CLI/测试同步（含"逐条已交付命令都不得残留在未就绪表"的反幽灵断言）→ 冒烟期望值改为真实契约 →
  README 退出码表与状态表）。落点见 `plan/07` 决策记录（2026-10-17 M1 收尾条）。

## M2 变更意图提取

**模块**：`src/agent_conflict_radar/intent.py`
**交付命令**：`radar intent --repo <path> [--claude-root P] [--codex-root P] [--out-dir D]`

### 输入

- M1 的活跃会话（含 `file` 与 `seq`，用于证据回指）；
- 目标仓库工作区（`git status --porcelain` / `git diff` / `git diff --cached`）。

### 处理

1. **工具调用抽取**（按会话类型分派）：
   - Claude：`Edit` / `Write` / `MultiEdit` 的 `file_path`；
   - Codex：`apply_patch` 载荷内的文件指令行。
2. **写操作记录**：每次写操作落 `{session_id, workspace, path, ts, old_string, new_string, patch_snippet, seq}`。
   - 文本字段**只截取定位所需的最小片段**（含行长上限），不整段复制会话正文（隐私，见 [03](03-架构与技术选型.md) §7.2）。
3. **磁盘对账**：以 `git status --porcelain` 与未提交 diff 确认"真实发生的变更"，产出改动行区间：
   - 能从 diff hunk 得到 → `precision="exact"`；
   - `replace_all` 或无法定位 → `precision="coarse"`；
   - 解析不到 `file_path` 的写操作 → `precision="unknown"` 并计入 `unknown_count`。
4. **聚合**：按 `(工作区, 文件)` 聚合；同一会话同文件多次写入按时间序合并，`last_write_ts` 取该组最大值。

### 输出

```json
{"entries":[{"workspace":"…","path":"src/alpha.py","sessions":["sess-radar-0001"],
             "last_write_ts":"2026-01-01T00:04:00Z","changed_ranges":[[10,20]],
             "precision":"exact","evidence":["alpha.py:12","diff:src/alpha.py@1"]}],
 "counts":{"entries":1,"exact":1,"coarse":0,"unknown":0}}
```

### 算法要点

- **落点三分法**：`exact` / `coarse` / `unknown` 三者互斥且穷尽，计数恒等式写进测试（`entries 的 precision 分布之和 == entries 条数`）。
- **不得猜测补全**：`file_path` 缺失就是 `unknown`，不从上下文"推断大概率是哪个文件"。
- **不伪造精确行区间**：`replace_all` 语义上覆盖全文 → 若无法给出确定区间就标 `coarse`，不得给一个"看起来精确"的区间。

### 确定性纪律

- 同一输入同输出；条目排序键 `(workspace, path)`，`sessions` 与 `evidence` 内部有序（去重后按首次出现序，不按 set 迭代序）。
- 不读时钟；`last_write_ts` 来自会话原值。

### 降级

- 非 git 目录中的会话：显式标注"非 git 工作区"，只做会话侧抽取，不做磁盘对账（`precision` 上限为 `coarse`），**不崩溃、不伪造冲突**。
- 会话正文超长行（超过行长上限）：显式报错并点名文件，不静默截断。

## M3 三级冲突检测

**模块**：`src/agent_conflict_radar/detect.py`（+ `gitio.merge_tree`）
**交付命令**：`radar detect --repo <path> [--out-dir D]`

### 输入

M1 的 `WorkspaceTable` + M2 的 `IntentSet` + 目标仓库的 git 对象（旧版/新版文件字节）。

### 处理（由粗到细，逐级给证据）

1. **文件级**：`(path)` 出现在两个**不同且活跃**的 `(workspace, session)` 组中 → `level="file"`，附各会话 `last_write_ts`。
   - 若两侧 `derived_from` 相同（同一父会话派生的 subagent）→ **默认不产出冲突**（场景 4），仅在开启提示配置时产出 `severity` 最低档并标 `derived_from`。
2. **区块级**：对同文件的两个版本执行
   `git merge-tree --write-tree <base> <other>`（**只读**：不写索引、不改工作区、不建分支），解析 stdout 的冲突路径与冲突块 → `level="block"`。
   - **降级**：缺共同祖先、单 commit 仓库、命令超时、git 不可用 → `degraded=True` 并落 `undetermined`（原因码 `degraded`），**不得抛"无冲突"**。
   - **边界如实披露**：`--write-tree` 会在对象库写入临时 tree 对象（不改索引与工作区）；报告与 README 明写，不得声称"零任何写入"。
3. **符号级**：用 Python `ast` 解析**旧版本与新版本**文件，提取 `FunctionDef` / `AsyncFunctionDef` / `ClassDef` / 方法（含限定名，如 `A.f`）的 `lineno`..`end_lineno`；把 M2 的 `changed_ranges` 映射到符号：
   - 两侧改动落在**同一符号** → `level="symbol"` + `symbol="A.f"` + 重叠/相邻行区间；
   - 落在**相邻符号**（行距 ≤ config 的相邻容差）→ `level="symbol"` + `approximate` 语义由 config 决定；
   - 落在同文件**不同符号** → 维持 `level="file"`（不升格）。
4. **非 Python 文件**：首期只做行区间近似 → `approximate=True`，`symbol=None`。
5. **严重度**：按 config 权重表打分（同一符号被两侧修改 > 同文件不同符号 > 行区间相邻 > 仅文件级同改），权重只从 config 读。
6. **依赖注入**：每条冲突带 `evidence`（会话 `file:seq`、diff hunk 引用、`merge-tree` 输出行）——必须能**手工复算**。

### 输出

```json
{"conflicts":[{"levels":["file","symbol"],"level":"symbol",
               "workspace_a":"…","workspace_b":"…","path":"src/alpha.py",
               "symbols":["f"],"line_ranges":[[10,14],[13,18]],"severity":50,
               "degraded":false,"approximate":false,
               "evidence":["claude:sess-radar-0001@alpha.jsonl:12","merge-tree:src/alpha.py@3"]}],
 "undetermined":[{"path":"src/x.py","code":"degraded","detail":"no merge base"}],
 "counts":{"conflicts":1,"by_max_level":{"file":0,"block":0,"symbol":1},
           "by_level_membership":{"file":1,"block":0,"symbol":1},"undetermined":0}}
```

**粒度口径（决定基准真值形态，M0 定稿于 `plan/07` 决策记录）**：

* 一条记录 = 一个 `(workspace_a, workspace_b, path)` 组合。
* `levels` = 该组合**命中的粒度集合**（`file` / `block` / `symbol` 的非空子集；同文件对被两活跃会话改 ⇒ 必含 `file`）。
* `level` = `levels` 中的**最高**粒度（只用于排序与严重度展示，不用于匹配）。
* `symbols` = 命中的符号限定名集合（同符号 ⇒ 单元素；跨相邻符号 ⇒ 可能是两个；仅文件级 ⇒ 空）。
* 真值按 `levels` / `symbols` **集合精确匹配**（多报、漏报均失败）。

> **为什么不是"只报最高粒度一条"**：题面场景 3 明确要求"文件级 + 符号级（被覆盖符号）"**同时**成立，
> 单一 `level` 字段表达不了。原设计（M0 写的"只报一条最高粒度"）与题面冲突，已按本条决策修正。

### 算法要点

- **行区间口径**：区间为 1-based 闭区间；"重叠"= 交集非空且交集行数 ≥ config 阈值；"相邻"= 间距 ≤ config 容差。
- **符号限定名**：嵌套类/函数用 `.` 连接（`A.B.f`）；同名不同作用域不同键（**不得**按裸名匹配）。
- **ast 失败**（语法错误/非 Python）：单文件降级 → `approximate=True` 或 `undetermined`，**不影响同批其他文件**（失败隔离）。
- **只读断言**：跑完 `merge-tree` 后工作区与索引 hash 前后一致（测试断言，K4）。

### 确定性纪律

- 同一输入同一次序：冲突排序键 `(level 序, severity desc, path, symbol or "", line_ranges)`。
- 同一文件对**只报一条**最高粒度的冲突（不重复计数）；`by_level` 计数与 `conflicts` 数组**按集合划分**恒等（`sum(by_level) == len(conflicts)`）。
- **绝不执行合并、绝不写 git 索引、绝不修改工作区**。
- AST 解析失败**标 `degraded`/`approximate`**，不得静默当"无冲突"。

### 计数口径（先声明，后实现，K12）

- `counts.conflicts` = **条目数**（一个 `(workspace_a, workspace_b, path)` 组合算一条）；
- `counts.by_max_level` = 条目数按 `level`（最高粒度）的**集合划分** → `sum(by_max_level) == len(conflicts)`；
- `counts.by_level_membership` = 各粒度在 `levels` 里出现的**成员数**（可大于条目数，因为一条可同时命中多级）
  ——**两栏分开登记**正是"计数口径先声明'条目数还是记录数'"的落地形态；
- `undetermined` **不计入** `conflicts`，独立分区。

## M4 预警与处置建议

**模块**：`src/agent_conflict_radar/report.py`
**交付命令**：`radar report --repo <path> [--out-dir D] [--format md|json|both]`

### 输入

M3 的 `ConflictSet`。

### 处理

1. **排序**：按 `severity` 降序，同分按 `(level, path, symbol)` 稳定排序。
2. **每条渲染**：粒度 / 文件 / 符号名 / 重叠行数 / 涉及 agent 与会话 id / 最后写入时间 / 建议。
   - 建议是**规则模板**（按 level 分派固定文案），不是模型判断：
     - `symbol` → "两侧并行改同一符号，需人工裁决"；
     - `file`（不同符号）→ "仅同文件不同符号，可先后提交"；
     - 行区间相邻 → "改动行区间相邻，建议由更早开始的会话先合并"。
3. **双轨输出**：
   - `report.md`：人读，含参数来源块（扫描窗口 / 活跃窗 / 阈值出处 `config/radar.toml`）、`undetermined` 独立小节、"判定为辅助参考"声明；
   - `conflicts.json`：机读，经 `serialize.py` 冻结契约（K2），供 M5 与 CI 消费。
4. **可选通知**：桌面通知不存在/不可用 → 静默跳过并在产物里标 `notify_unavailable`，**不影响主流程与退出码**。
5. **退出码**：`conflicts` 非空 → `1`；为空且无 `undetermined` → `0`；存在 `undetermined` → 仍按冲突有无给码，但报告显式列出（**不得**因为"没底"而给 `0` 又不提示）。

### 输出与退出码语义

| 码 | 语义 | 触发 |
|---|---|---|
| `0` | 无冲突 | `conflicts == []` |
| `1` | 有冲突 | `conflicts != []` |
| `2` | 用法错误 | 未知子命令 / 缺必填参数 / 未知 `--format` / 路径不存在 |
| `3` | 依赖或环境缺失 | git 不可用 / 配置缺失或不可解析 / 会话源不存在 |
| `4` | 阶段未就绪 | 骨架期专用，逐阶段退役（K1） |

### 确定性纪律

- 报告排序稳定、字段稳定；**渲染层零判定**：只消费既有结论，不重算任何判定（AST 门禁断言 `report.py` 不 import `detect` 的判定函数、不含比较阈值字面量）。
- 时间一律呈现原值，**不编造**"预计完成时间"类推断。
- 零外链：`report.md` 不含任何外部资源引用（无图片外链、无 CDN、无 http(s) 链接除非是用户输入里的既有 URL 且只作文本）。断言常驻渲染出口（`assert_no_external_resources`）。
- 双跑逐字节一致。

## M5 合成基准（核心交付）

**模块**：`src/agent_conflict_radar/bench.py` + `src/agent_conflict_radar/bench/gen.py`
**交付命令**：`radar bench [--bench-dir D] [--out-dir D] [--only ID,...]`；生成器侧 `python -m agent_conflict_radar.bench.gen [--out DIR] [--check]`

> 生成器放**包内**（`agent_conflict_radar.bench.gen`）而非仓库顶层目录：顶层目录不进安装面会让"装好的 console script"报 `ModuleNotFoundError`（SKILL 菜谱成本核算器 M6 头号发现的形态）。

### 输入

程序化生成的临时 git 仓库（临时目录 + `git init` + 确定性提交）+ 合成 agent 会话日志（白名单假值）。

### 场景矩阵（每组都必须植入真值）

| # | 场景 id | 构造 | 期望判定 |
|---|---|---|---|
| 1 | `same_file_diff_symbol` | 两会话分别改 `alpha.py` 的 `f()` 与 `g()` | **文件级冲突**；符号级**不得**报同一符号 |
| 2 | `same_symbol_diff_lines` | 两会话改同一函数首尾两段 | **符号级冲突** + 重叠/相邻行区间 |
| 3 | `whole_file_overwrite` | 一侧 `Write` 覆盖整文件、另一侧局部 `Edit` | **文件级 + 符号级（被覆盖符号）** |
| 4 | `subagent_derived` | 同一 parent 派生的 subagent 并行 | 标注 `derived_from`；**默认不报**跨 agent 冲突 |
| 5 | `negative_no_overlap` | 两会话改完全不重叠的文件 / 时间窗不重叠 | **空检出**（防误报） |
| 6 | `threshold_adjacent` | 同文件两侧改动间隔大于阈值 | 按配置判定（测阈值口径） |

### 处理

1. 生成器为每个场景产出：临时仓库 + 会话日志 + `*.truth.json`（**同步产出，不得事后手补**）；
2. `radar bench` 在冻结产物上跑完整链路（scan → intent → detect），逐场景把**实际检出集合**与真值对账；
3. 对账按**集合精确匹配**：多报（`extra`）、漏报（`missing`）**均计失败**；
4. 逐场景打印 `期望 / 实际 / 判定`，并汇总覆盖率与失败清单（落 `bench/last_run.json`）。

### 真值格式（`*.truth.json`，只存输入与期望，K9）

```json
{"scenario":"same_symbol_diff_lines","level_expected":["symbol"],
 "objects_expected":[{"path":"src/alpha.py","symbol":"f"}],
 "objects_forbidden":[{"path":"src/alpha.py","symbol":"g"}],
 "sessions":["sess-radar-0001","sess-radar-0002"],
 "notes":"两会话改同一函数首尾两段"}
```

- **禁止**出现 `observed_*` 一类字段（冻结"观测"会让基准退化成"比对两份预先算好的答案"，引擎全坏也全绿）；
- 期望值必须**可由输入独立复算**（把检测引擎注释掉，真值仍算得出来）；
- `objects_forbidden` 是**反向样例**：只测"该命中"的用例，适用域写错永远不会红。

### 覆盖度门槛

覆盖率口径写进 `bench/manifest.json` 的 `coverage.min_count_by_type`：每类场景的最低条数；缺类**不得**用别的类凑（`missing_types` 显式列出）。

### 确定性纪律

- 合成仓库与日志用白名单假值（K11）：假项目名 / 假包名 / 假路径 / 假 session id / 假用户名 `radar-user` / 假分支 `feat/agent-a`·`feat/agent-b` / 固定基准时间 `2026-01-01T00:00:00Z` 起的确定偏移；
- 生成器**禁 stdlib `random`、禁 set 迭代序、禁系统时钟**；产物无时间戳字段；
- `--check` 重生成到临时目录 → 与冻结产物**逐字节一致**（两层断言：冻结产物形态 + 重生成结果，见 K10）；
- `git commit` 需固定作者/时间（`GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE`）以保提交 sha 稳定。
