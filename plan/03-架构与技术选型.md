## 一、分层架构（五层，依赖单向向下）

```
┌──────────────────────────────────────────────────────────────────────┐
│ L5 入口层        cli.py（argparse 子命令 / 退出码 / 编码守卫）        │
│                  __main__.py（python -m 通路）                        │
├──────────────────────────────────────────────────────────────────────┤
│ L4 交付层        report.py（report.md 人读 + conflicts.json 机读）    │
│                  （M4）                                               │
├──────────────────────────────────────────────────────────────────────┤
│ L3 判定层        detect.py（文件级 → 区块级 → 符号级）                │
│                  （M3）  bench.py（合成矩阵 + 真值对账，读 L1/L3）    │
├──────────────────────────────────────────────────────────────────────┤
│ L2 提取层        discover.py（M1 工作区与会话发现）                   │
│                  intent.py  （M2 变更意图提取）                       │
├──────────────────────────────────────────────────────────────────────┤
│ L1 基建层        config.py（唯一数值权威 + TOML 子集解析器）          │
│                  gitio.py（git 只读封装：worktree/status/diff/merge-tree）│
│                  serialize.py（唯一写盘点 + 冻结序列化契约）          │
│                  versions.py（会话格式指纹 + 显式版本集合）           │
│                  errors.py（错误类型 → 退出码映射）                   │
└──────────────────────────────────────────────────────────────────────┘
```

**依赖纪律**：
- 上层可依赖下层；**下层禁止 import 上层**（用 AST 守门断言，见 K5 同族的 import 面门禁）。
- `detect.py` 零判定逻辑不得出现在 `report.py` —— 渲染层只消费既有结论，**不重算任何判定**。
- `config.py` 是**唯一**读取 `config/radar.toml` 的模块；其他模块一律经它取值。

## 二、数据流

```
  git worktree list --porcelain ─┐
  Claude 会话 jsonl ─────────────┤
  Codex  会话 jsonl ─────────────┴─→ [M1 discover] ──→ WorkspaceTable
                                        │                 {worktrees[], sessions[], active_cells[]}
                                        │
  git status / git diff / git diff --cached ─→ [M2 intent] ──→ IntentSet
  （会话内 Edit/Write/MultiEdit/apply_patch）                    {entries[]}
                                        │
                                        ▼
  git 对象（旧版/新版文件字节） ─→ [M3 detect]
                                      ├─ 文件级：两活跃工作区同文件
                                      ├─ 区块级：git merge-tree --write-tree（只读试合并）
                                      └─ 符号级：ast 行区间/限定名比对
                                        │
                                        ▼
                                   ConflictSet {conflicts[level,workspace_a/b,path,symbol?,line_ranges,evidence,severity]}
                                        │
                     ┌──────────────────┴──────────────────┐
                     ▼                                     ▼
              [M4 report]                            [M5 bench]
              report.md + conflicts.json             合成矩阵 → 检出集合 vs 真值
              （退出码 0/1）                          （exit 0 全匹配 / exit 1 有差异）
```

**只读边界（K4）**：数据流中所有对 git 的调用都是**只读**——`worktree list` / `status` / `diff` / `merge-tree --write-tree`。全链路**不写索引、不建分支、不改工作区**；唯一写盘目标是用户指定的 `--out-dir`（默认当前目录），且只写 `report.md` / `conflicts.json`。

## 三、模块接口（签名级约定，M0 冻结）

> 下列类型在 M0 骨架里以 `dataclass` 形式落地（仅结构 + 序列化，不含判定逻辑）；字段名一经冻结即为**动了会打挂基准**的口径。

### 3.1 M1 `discover.py`

```python
@dataclass(frozen=True)
class Worktree:      path: str; head: str; branch: str; is_main: bool
@dataclass(frozen=True)
class Session:       source: str        # "claude" | "codex"
                     session_id: str
                     cwd: str
                     git_branch: str | None
                     start_ts: str      # 原样字符串，ISO8601（不读时钟）
                     end_ts: str
                     derived_from: str | None   # parent session id；独立会话为 None
                     file: str          # 来源文件相对路径（相对 --*-root）
                     seq: int           # 源文件行号（非数组下标）
@dataclass(frozen=True)
class ActiveCell:    source: str; session_id: str; workspace: str
                     window_start: str; window_end: str
                     is_subagent: bool; derived_from: str | None
@dataclass(frozen=True)
class WorkspaceTable: worktrees: tuple; sessions: tuple; active_cells: tuple

def build_workspace_table(repo, claude_root, codex_root, cfg) -> WorkspaceTable
```

### 3.2 M2 `intent.py`

```python
@dataclass(frozen=True)
class IntentEntry:   workspace: str; path: str
                     sessions: tuple[str, ...]
                     last_write_ts: str
                     changed_ranges: tuple[tuple[int, int], ...]   # 1-based 闭区间
                     precision: str      # "exact" | "coarse" | "unknown"
                     evidence: tuple[str, ...]   # "文件:行号" 或 "diff hunk 引用"
@dataclass(frozen=True)
class IntentSet:     entries: tuple; unknown_count: int; coarse_count: int

def build_intent_set(table: WorkspaceTable, repo, cfg) -> IntentSet
```

### 3.3 M3 `detect.py`

```python
@dataclass(frozen=True)
class Conflict:      level: str          # "file" | "block" | "symbol"
                     workspace_a: str; workspace_b: str
                     path: str
                     symbol: str | None
                     line_ranges: tuple
                     evidence: tuple
                     severity: int       # 权重读自 config
                     degraded: bool      # 试合并/AST 失败降级
                     approximate: bool   # 非 Python 行区间近似
@dataclass(frozen=True)
class ConflictSet:   conflicts: tuple; undetermined: tuple   # undetermined 独立分区，不混入结论

def detect_conflicts(repo, table, intents, cfg) -> ConflictSet
```

### 3.4 M4 `report.py`

```python
def render_markdown(cset: ConflictSet, cfg, meta: dict) -> str
def render_json(cset: ConflictSet, cfg, meta: dict) -> str       # 经 serialize 冻结契约
def exit_code_for(cset: ConflictSet) -> int                      # 0 / 1
```

### 3.5 M5 `bench.py`

```python
def list_scenarios() -> tuple[str, ...]                          # 有序、冻结
def run_bench(bench_dir, out_dir, cfg) -> BenchResult            # 逐场景对账
# BenchResult: scenarios[] 每项 {id, level_expected, objects_expected, actual, verdict}
# verdict ∈ {"pass", "missing", "extra", "error"}；extra/missing 均计失败
```

## 五、技术选型与理由

| 选型 | 决定 | 理由 / 备选与否决原因 |
|---|---|---|
| 语言 | Python（≥3.8） | 标准库 `ast` / `json` / `subprocess` / `pathlib` 足够；`ast` 是符号级检测的关键依赖，自研替代成本极高 |
| 依赖 | **零第三方运行时依赖** | 隐私与可复现：用户 `pip install .` 秒装、断网可跑；避免"安装面"类缺陷 |
| 测试期依赖 | `pytest`（仅 dev extra） | 与 README 快速开始那条安装命令、CI 全部 job 用**同一 extras 集合**（K-extras 对账门） |
| 配置格式 | **自写受限 TOML 子集解析器**（不用 `tomllib`） | 底线解释器 3.8 无 `tomllib`（3.11+ 才有）。**不引入运行时依赖、也不静默跳过**——支持 `[section]` / `key = 标量` / 数组 / 注释，遇到超集形态显式报 `toml_unsupported`（见 K6 同族纪律）。单一实现跨解释器一致，避免"3.12 能读 3.8 读不出"的分叉 |
| 会话解析 | **按首行文件形态判别归属**（`message` vs `payload`），不按目录名 | 目录名是"我们约定的"会漂；文件形态是源工具产出的稳定事实。且真实布局与合成夹具走同一条通路 |
| 版本检测 | 显式版本指纹集合，**不在集合内即报错** | 比"按最宽松规则解析"贵（新版本要手写进 `versions.py`），换来"未知版本一定报错而非静默错解" |
| 试合并 | `git merge-tree --write-tree` | git 官方无副作用试合并；**边界如实披露**：会在对象库写临时 tree 对象（不改索引、不改工作区），报告中不得声称"零任何写入" |
| 符号级 | Python `ast`（`FunctionDef`/`AsyncFunctionDef`/`ClassDef` 的 `lineno`/`end_lineno` + 限定名） | 零依赖、行区间可复算；非 Python 首期降级为行区间近似并标 `approximate` |
| 序列化 | 自写最小 writer：`json.dumps(sort_keys=True, ensure_ascii=False, indent=2)` + LF + 结尾换行 + 原子写 | 中文可读（`ensure_ascii=False`）；字节确定性；不引第三方保字节确定 |
| 退出码 | `0` 无冲突 / `1` 有冲突 / `2` 用法错误 / `3` 依赖或环境缺失 / `4` 阶段未就绪（骨架期专用，逐阶段退役） | 前四个来自题面 §M4；第五个是骨架期"不伪造空结果"的显式拦截，走固定退役流程（K1） |
| 交付形态 | 纯本地 CLI（无 GUI / 无 exe / 无服务器） | 题面 §三 明示唯一形态；形态收敛避免"名义支持" |
| 并发 | **不引入并发**，全程串行确定性 | 冲突检测不需要并行；引入线程/异步会给"同输入同输出"引入非确定源 |

## 六、风险与对策

| 风险 | 影响面 | 对策（可验证） |
|---|---|---|
| 同类多且低星（题面 §1.4） | 定位说服力 | 不写"需求已验证"；README 与报告只写"存在公开抱怨 + 本机样本为 0"；差异化押符号级 + 会话进行中 |
| `wit` 已口头占位符号级 | 创新性评分 | 不宣称首创；对外表述限定为"会话进行中的实时符号区间比对 + worktree 拓扑 + 可复现冲突矩阵三者同时覆盖" |
| 本机真实并行冲突样本为 0 | 检出能力无法用真实数据证明 | 验收主体 = 合成冲突矩阵 + 植入真值；报告与 README 明写分母来自合成基准 |
| 会话格式随 harness 演进 | 解析静默失配 | 版本指纹显式集合 + 未知版本报 `unsupported_format` 并列出缺失键（K7）；R1–R3 待核对项 M1 闭环 |
| `merge-tree` 在无共同祖先/单 commit 仓库下的输出形态未知（R1） | 区块级误降级 | M1 先做只读探针实测并把结论写进 `data/README.md` 闭环表；未闭环前该路径只允许落 `degraded`，不得进判定 |
| Windows 路径两套写法（Git Bash `~` vs Python） | 找不到源、误报空结果 | 一律 `os.path.expanduser` + `pathlib`；守卫：`expanduser` 解不出主目录时**按哨兵比对**，不写不抛不回落 CWD（见 K16） |
| 大文件/超长行 JSONL | 内存与解析异常 | 逐行读取设行长上限并显式报错，不静默截断 |
| 报告被读成"安全证明" | 定位失真 | 报告首段固定声明"判定为辅助参考，处置由你决定"；反方观点（HN 47626971）写进 README |
| CI 环境差异（cp1252 / 非 ASCII 输出） | 本机全绿、CI 全红 | 入口 `_ensure_utf8_stdio()` 按 `stream.encoding` 探针决定是否 reconfigure + 子进程显式 `encoding=` + CI `PYTHONUTF8=1`（K8） |
| `python -m` 与裸 `radar` 是两条通路 | "我们的包没进安装面"类缺陷潜伏 | CI 两种形态都冒烟（K15）；`pyproject` 只用 `src` 布局 + `where=["src"]`，不引入"包外目录" |

## 七、确定性与隐私设计

### 7.1 确定性（K2 / K10 的架构落地）

| 来源 | 处置 |
|---|---|
| 系统时钟 | **全程不读时钟**；所有时间戳取自会话/文件原值 |
| 字典/set 迭代序 | 遍历一律先排序成 list 再消费；排序键全部可从输入复算 |
| JSON 序列化参数 | 全仓唯一写盘点 `serialize.py`，参数冻结（K2） |
| 生成器 | 自研确定性 RNG（splitmix64 风格），**禁 `random`、禁系统时钟**；产物无时间戳字段 |
| 事件序号 | `seq` = **源文件行号**，不是数组下标（下标会随过滤漂移） |
| 浮点 | 首期不用浮点参与判定（行号/权重均为整数） |

### 7.2 隐私（题面 §六 红线）

| 面 | 措施 |
|---|---|
| 网络 | 全仓零网络调用；`tools/verify_offline.py` 在 CI 里做导入面审计 |
| 会话正文 | 检测链路**不落 prompt 正文**：只抽 `cwd`/`gitBranch`/时间戳/`file_path`/`old_string`/`new_string`；证据只记 `文件:行号`，不复制长文本 |
| 入库 | 真实日志/真实路径清单/真实 session id **零入仓**；`.gitignore` 已屏蔽 `sessions/`、`exports/`、`**/_real_logs/`、`data/**/_private/` |
| 公开仓库 | 只含合成场景；合成值走白名单（K11） |
| 声明 | README 与 `--help` 明示"纯本地、零上传、零遥测、不联网"；审计范围与措辞对齐（源码 import 面 + 产物面 + 动态拦截面，M6 落档） |

## 八、关键技术决策的"已核对/待核对"三态

| 项 | 状态 | 说明 |
|---|---|---|
| `git worktree list --porcelain` 输出可解析 | ✅ 已核对（本机 git 2.54.0） | 按行解析，不按空格切分 |
| `git merge-tree --write-tree` 命令形态可用 | ✅ 已核对（`git merge-tree -h` 显示 `--write-tree`） | **边界**：写对象库临时 tree |
| Python `ast` 行区间 | ✅ 已核对（标准库，3.8+ 有 `end_lineno`） | 注意：`end_lineno` 是 3.8 引入，底线解释器满足 |
| 双 harness 会话字段形态 | 🔶 M0 骨架按题面/data README 描述建模，**标为待 M1 实测勘误** | R1–R3 见 [../data/README.md](../data/README.md) §五 |
| Claude `MultiEdit` 是否出现 / `edits[]` 结构 | ⬜ 待核对（R3，M1 闭环） | 未闭环前该形态只落 `unknown` 并计数 |
| Codex `apply_patch` 载荷内路径字段形态 | ⬜ 待核对（R2，M1 闭环） | 同上 |
