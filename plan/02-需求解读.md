## 一、痛点 → 能力转译

| # | 痛点（出处见题面 §1.1 / data README §1.1） | 现有工作流为什么拦不住 | 本题转译成的**能力** | 由哪条命令产出 | 由哪条基准断言 |
|---|---|---|---|---|---|
| P1 | 一个 agent 悄悄覆盖另一个的工作，直到合并才发现（HN 47324913） | 冲突在**合并时**才由 git 暴露，而覆盖发生在**写入时** | 在写入发生前，把"谁正在改什么"落到 `(工作区, 文件, 行区间, 符号)` 上并求交集 | `radar detect` → `conflicts[]` | 合成矩阵场景 1/2/3 |
| P2 | worktree 类工具不自动处理合并冲突（HN 48238822） | 编排器只管"起几个 agent"，不管"它们会不会撞" | 把 worktree 拓扑纳入比对维度（同一文件在两个**活跃** worktree 中改 = 文件级冲突） | `radar scan` + `radar detect` | 合成矩阵场景 1/3 |
| P3 | 无锁定时两个 agent 抢同一任务（HN 47289444） | 没有跨会话的共享状态能回答"这个文件现在有谁在动" | **跨会话的本地持久状态归集**：读双 harness 会话日志 + 未提交 diff，建立"活跃 agent × 工作区 × 时间窗"表 | `radar scan` → `active_cells[]` | 合成会话对账 + 同输入双跑逐字节一致 |
| P4 | 反方：独立 worktree + 人工合并会让 git 在合并时拦下（HN 47626971） | ——（这条**部分成立**，是本题的边界而非痛点） | 本工具的价值定位收敛为**提前量**（省返工/省覆盖损失），**不是安全边界** | 全部输出 | 报告措辞门禁（不得声称"防止所有覆盖"） |
| P5 | 相同 parent 派生的 subagent 并行被误读成"两个 agent 冲突"（题面 §1.3 本机唯一 3 例） | 日志里 subagent 与独立会话混在一起 | `derived_from` 派生标注 + 默认不报跨 agent 冲突 | `radar scan` 的 `derived_from` + `radar detect` 的过滤 | 合成矩阵场景 4 |

**一句话收敛**：把"覆盖发生的那一秒"与"合并暴露的那一刻"之间那段无人比对的时间，用**本地只读的四级粒度冲突矩阵**填上。

## 二、FR 功能清单（带优先级）

> 优先级口径：**P0** = 首期必达（缺则题面 §四 功能实现效果/应用完整性失分）；**P1** = 首期应达（影响创新性/表现力评分）；**P2** = 扩展项（§2.6，不承诺首期）。

### FR-1 工作区与会话发现（对应 M1）

| ID | 功能 | 优先级 |
|---|---|---|
| FR-1.1 | 用 `git worktree list --porcelain` 枚举主工作区与各 worktree（路径/HEAD/分支），按行解析（不按空格切分） | P0 |
| FR-1.2 | 扫描 Claude Code 会话（`<claude-root>/**/*.jsonl`），抽取 `cwd` / `gitBranch` / 时间戳 | P0 |
| FR-1.3 | 扫描 Codex 会话（`<codex-root>/**/*.jsonl`），抽取工作目录 / 时间戳 | P0 |
| FR-1.4 | 按**文件形态**判别归属（首行 JSON 有 `message` 还是 `payload`），**不按目录名**判别 | P0 |
| FR-1.5 | 会话格式版本指纹检测：不认识的版本**显式报 `unsupported_format` 并列出缺失键**，绝不静默产出空表 | P0 |
| FR-1.6 | 建立"活跃 agent × 工作区 × 时间窗"表；窗长口径来自 `config/radar.toml` | P0 |
| FR-1.7 | 识别 parent/child 关系，subagent 标 `derived_from`，与父会话去重 | P0 |
| FR-1.8 | 路径自适应：`--repo` / `--claude-root` / `--codex-root` / 环境变量 / 常见位置探测；**不硬编码用户名** | P0 |
| FR-1.9 | 找不到会话源时显式报错（**不得**退化为空结果 exit 0） | P0 |

### FR-2 变更意图提取（对应 M2）

| ID | 功能 | 优先级 |
|---|---|---|
| FR-2.1 | 解析 Claude `Edit` / `Write` / `MultiEdit` 的 `file_path` | P0 |
| FR-2.2 | 解析 Codex `apply_patch` 的文件指令行 | P0 |
| FR-2.3 | 每次写操作记录：时间戳 / 旧文本 / 新文本 / 补丁片段 / 会话 id / 工作区 | P0 |
| FR-2.4 | 用 `git status --porcelain` + `git diff` + `git diff --cached` 与磁盘真实变更对账 | P0 |

### FR-3 三级冲突检测（对应 M3）

| ID | 功能 | 优先级 |
|---|---|---|

## 三、用户旅程（三条，均为首期可演示路径）

**旅程 A：单机多窗口自查（主打）**
```
1. 用户同时开了 2–3 个 Claude Code / Codex 窗口改同一个仓库
2. $ radar detect --repo .            # 一条命令
   → 终端打印冲突清单（符号级在前），退出码 1（有冲突）
3. $ radar report --repo . --out-dir out/
   → out/report.md 人读 + out/conflicts.json 机读
4. 用户按建议处置（"更早开始的会话先合并" / "同符号需人工裁决"），本工具不代劳
```

**旅程 B：合成场景演示（可复现、零隐私）**
```
1. $ radar bench                      # 生成矩阵 → 跑检测 → 对账真值
   → 逐场景打印"期望/实际/判定"，退出码 0（全部精确匹配）
2. 重复运行逐字节一致（K10 生成序单点定义 + K2 序列化冻结契约）
```
> 旅程 B 是**验收主体**：题面 §1.3 已披露本机真实并行冲突样本为 0，检出能力只能由植入真值的合成矩阵断言。

**旅程 C：只读演示（本机真实会话，仅作可行性展示）**
```
1. $ radar scan --repo . --claude-root <本机> --codex-root <本机>
   → 打印 worktree 表 + 活跃会话 cell 表（不含 prompt 正文）
2. 全程零写盘（输出仅 stdout / 指定 --out-dir），零网络
```
> 旅程 C 的结论**只作演示**：不得据此宣称"检出率"，不得把真实会话条数包装成需求验证。

## 四、边界与非目标（防 scope 失控）

| 类别 | 非目标 | 理由 |
|---|---|---|
| 处置 | **不自动合并、不自动解决冲突、不写 git 索引、不执行 merge/rebase、不修改任何代码文件** | 自动处置引入正确性责任与破坏用户工作区的风险；定位是"预警"不是"裁决" |
| 编排 | 不做任务分配、不启动/停止 agent、不做锁服务 | 编排方向已饱和（题面 §1.2 高星均为编排器） |
| 覆盖面 | 首期只覆盖 Claude Code + Codex + git 工作区 | 会话格式随 harness 演进、差异大；避免"名义支持" |
| 隐私 | 纯本地零上传；真实日志/真实路径清单/真实 session id 一律不入仓 | 会话日志含 prompt 与代码 |
| 品牌 | 不复制同系列其他项目代码；公开文档不提及任何其他项目名称与业务领域 | 品牌隔离（题面 §六） |
| 兼容 | 不承诺会话格式跨版本兼容；不认识的新格式显式报错，不猜测 | 解析器以"本机实测字段 + 版本指纹"为依据 |
| 结论强度 | 不声称"防止所有覆盖"；不声称"需求已验证"；不宣称符号级首创（`wit` 已口头占位） | 题面 §1.4 三项风险如实披露 |

## 五、验收口径

### 5.1 三态判定语义（不虚高）

每条冲突项只有三种结论，**没有第四种**：

| 结论 | 含义 | 触发条件 |
|---|---|---|
| `conflict` | 判定为冲突 | 满足对应粒度的判据且证据完整 |
| `no_conflict` | 判定不为冲突 | 判据可执行且不成立 |
| `undetermined` | **判据执行不了**（缺共同祖先 / AST 解析失败 / 未识别格式 / 依赖缺失） | 必须带原因码（`degraded` / `approximate` / `unsupported_format` / `dependency_missing`）**并计入统计**，绝不写成 `no_conflict` |

> 判别纪律：**"没查出问题"与"没检查过"必须可区分**。`undetermined` 不得被读成"安全"；报告里独立成节列出。

### 5.2 口径定义（数值一律引用 `config/radar.toml`）

| 口径 | 定义位置 | 说明 |
|---|---|---|
| 活跃时间窗 | `config/radar.toml` | 会话最后一次写操作后仍视为活跃的时长 |
| 会话扫描窗口 | 同上 | 只扫描窗口内的会话 |
| 符号重叠/相邻行数阈值 | 同上 | 判定"重叠"与"相邻"的行数口径 |
| 严重度权重与排序 | 同上 | 四级严重度权重 |
| git 命令超时 | 同上 | 子进程超时，防挂死 |

### 5.3 交付路径 == 验收路径

全部 DoD 与评分项都打在 CLI 命令上：`radar scan` / `intent` / `detect` / `report` / `bench` / `selftest` / `config`。基准也从同一 CLI 入口跑（`radar bench`），不存在"只在测试里能跑"的验收路径。

### 5.4 反假绿口径（M0 起生效）

- **单边门不算门**：既守误报率 0，也守检出率（真值库全量实跑 + 逐样本点名 + 错误类型归属逐样本核对）。
- **假门判别**：删掉被测逻辑，测试必须变红；"测试仍绿"就是假门。
- **探活打在消费处**：注入缺陷后重跑同一套 check 必须报出差异。
- **桩哨兵**：收尾期扫 `NotImplementedError` / `TODO: 实现` / `placeholder`，防空桩混过里程碑。
