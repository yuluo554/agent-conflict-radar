## 一、数据底座结论（一句话）

**验收主体是程序化合成，不是真实数据。** 本机实测：309 对时间重叠会话、63 个独立会话、独立重叠 22 对、**同文件重叠 0 对**（基准日 2026-10-17）。因此：

| 数据角色 | 用途 | 是否支撑"检出率"类结论 |
|---|---|---|
| **合成冲突矩阵**（植入真值） | **验收主体**：检出集合精确匹配、负样本零误报 | ✅ 是（分母来自合成基准，必须注明） |
| 本机真实会话 | 可跑性演示 + 人工抽验（旅程 C） | ❌ 否（样本为 0，只作可行性说明） |
| GitHub 检索计数 | 选题背景（软论据 ⬜） | ❌ 否 |

> 任何"检出率 / 准确率"表述必须注明**分母来自合成基准**；不得用真实样本数包装（题面 §1.3 的诚实结论原样生效）。

## 二、目录布局与职责

```
data/
├── README.md            # 依据查证 / 本机实测 / 合成数据纪律 / 数值口径纪律（已定稿，唯一台账）
└── samples/             # （按需）只读探针的原始响应/输出字节，含 URL·日期·sha256；M1 起按需落
bench/                   # 合成矩阵冻结产物（生成物，禁手改）
├── manifest.json        # 冲突场景清单 + 覆盖度门槛 + 生成器版本 + 每个真值的 sha256 台账（M1）
├── scenarios/
│   └── <scenario_id>/
│       ├── repo/        # 合成仓库的**基线**源码（纯文本；`.git` 不入仓，见下）
│       ├── sessions/    # 合成会话日志（claude/*.jsonl、codex/*.jsonl）
│       └── truth.json   # 植入真值（生成时同步产出，K9）
├── intents/             # M2 意图矩阵（独立冻结树，见 §九）
│   ├── manifest.json    # 意图场景清单 + 覆盖度门槛 + 每条真值的 sha256
│   └── <scenario_id>/
│       ├── repo/        # 基线 = M1 基线 + src/dup.py（歧义锚点）+ docs/notes.md（非 Python）
│       ├── sessions/    # 合成会话日志（含 staged/unstaged 的未提交改动声明）
│       └── truth.json   # entries_expected + unknown_expected + counts_expected + geometry
└── last_run.json        # `radar bench` 最近一次对账结果（M5 交付；**运行产物**，不是生成物——
                        #   `--check` 的逐字节比对面单名放行它，仍受「机器无关」约束）
```

> **M1 实测修正（2026-10-17）**：初稿写的是 `repo.git/`（把真 `.git` 一起冻进去）。实测后改判为
> `repo/`（只冻**基线文本**），理由有两条，都不是"图省事"：
> ① `.git` 内部字节取决于 zlib/git 版本与随机化的临时文件名，跨平台**不可能**逐字节重现——
> 把它纳入 `--check` 的逐字节比对会让 CI 四腿同点全红（假红）；
> ② 提交的可复现性另有**更强**的判据：提交 sha 记进真值，`--check` 重新物化仓库并复算 sha
> （sha 只由内容 + 固定元数据决定，跨平台稳定）。物化入口：
> `python -m agent_conflict_radar.bench.gen --materialize <id> --dest <dir>`。
> 另：会话日志里的会话根写作占位符 `{{REPO_ROOT}}`（物化时替换）——冻结产物**不得登记
> 环境依赖事实**，否则"在别人电脑上 `--check` 必红"（§六 同名纪律的落地）。

> **`bench/` 是数据不是代码**：包内可导入的是生成器（`agent_conflict_radar.bench.gen`），`bench/` 只作冻结数据。README 的 `radar bench` 默认从仓库根的 `bench/` 解析；解析不到时按 `--bench-dir` 显式传（安装面纪律，见 [03](03-架构与技术选型.md) §六）。

## 三、合成数据白名单（零真实值）

| 类别 | 白名单值 | 禁止 |
|---|---|---|
| 假项目名 | `demo-radar-alpha` / `demo-radar-beta` | 真实项目名/仓库名 |
| 假包名 | `demo_radar_alpha` / `demo_radar_beta` | 真实包名、域名反写 |
| 假文件路径 | `demo-radar-alpha/src/alpha.py`、`demo-radar-beta/pkg/beta.py` | 真实路径 |
| 合成仓库内相对路径（**M1 追加**） | `src/alpha.py`（主场景文件）、`src/beta.py`（"另一侧改的文件"）、`src/filler.py`（rng 生成的**噪声**文件，两个会话都不碰它） | 任何真实路径 |
| 意图矩阵追加路径（**M2 追加**） | `src/dup.py`（歧义锚点专用：同一段 2 行出现两次）、`docs/notes.md`（非 Python 文件，R4 闭环实物） | 任何真实路径 |
| 会话根占位符（**M1 追加**） | `{{REPO_ROOT}}`——冻结产物里代表"被物化的合成仓库根"，物化时替换为本机路径 | 把本机绝对路径冻进产物 |
| 假 author（**M1 追加**） | `radar-user` / `radar-user@example.invalid` | 真实署名与邮箱 |
| 假 session id | `sess-radar-0001` 起的固定序列（M1 用到 `sess-radar-0001`–`0015`；**M2 用到 `sess-radar-0020`–`0026`**，跨场景连续分配） | 真实 UUID |
| 假用户名 | `radar-user` | 真实用户名 |
| 假分支 | `feat/agent-a` / `feat/agent-b` | 真实分支名 |
| 假时间戳 | 固定基准 `2026-01-01T00:00:00Z` 起的**确定偏移** | 真实会话时间 |

> **M1 追加的理由**：`src/beta.py` 是负样本场景（`negative_no_overlap`）必需的"第二个文件"——
> 用 `demo-radar-beta/pkg/beta.py` 当同仓库里的第二个文件会让"仓库名"与"文件路径"互相矛盾，
> 反而更难核对；`src/filler.py` 是噪声文件，让"不误报无关文件"这条断言有实物可打。
> 三者都仍在 **`demo-radar-alpha`** 这个假项目名下，白名单纪律不变（零真实值）。
>
> **M2 追加的理由**：`src/dup.py` 的存在是为了让"锚点两处命中"有**实物**可打——在 `alpha.py` 里造重复行
> 会扰动 M1 的符号几何，两套真值不该共用同一份基线；`docs/notes.md` 是 R4 闭环口径（非 Python 文件的
> 行区间近似）的唯一实物。两个文件都只在 `bench/intents/` 里出现，不进 M1 的冲突场景。
> 假 session id 段随之顺延到 `0026`，仍在一段可审计的固定序列内（不是随机 UUID）。

**入仓前扫描**：真实路径清单、真实 session id、真实用户名在本仓 0 命中（M5 守门 + M6 脱敏复查）。

## 四、真值语义（一次定清）

### 4.1 真值只存"输入与期望"

```json
{"scenario":"same_symbol_diff_lines",
 "level_expected":["symbol"],
 "objects_expected":[{"path":"src/alpha.py","symbol":"f"}],
 "objects_forbidden":[{"path":"src/alpha.py","symbol":"g"}],
 "sessions":["sess-radar-0001","sess-radar-0002"],
 "notes":"两会话改同一函数首尾两段"}
```

四条硬纪律：

1. **禁 `observed_*` 字段**：出现即红（冻结"观测"会让基准退化成"比对两份预先算好的答案"——引擎全坏也全绿）。
2. **期望值必须可由输入独立复算**：判别 = **"把检测引擎注释掉，真值还能算出来吗？"** 不能 → 期望值与引擎同源（引擎自证），必须重做。
3. **生成器与真值同步产出**：真值**不得事后人工补**（手补的真值会悄悄向实现对齐）。
4. **每组场景必须带 `objects_forbidden`（反向样例）**：只测"该命中"的用例，适用域/阈值写错永远不会红。

### 4.2 场景 → 真值 → 断言映射

> 期望值由**构造几何 + 题面口径**决定，并用 M1 的 `merge-tree` 实测（`data/README.md` §6.1）
> 确定"git 会不会自己报冲突"。期望值**不由运行检测引擎得出**（否则引擎自证）。

| # | 场景 id | 构造（几何） | `levels_expected` | `levels_forbidden` | `symbols_expected` | 依据 |
|---|---|---|---|---|---|---|
| 1 | `same_file_diff_symbol` | 两会话分别改 `alpha.py` 的 `f()` 与 `g()`（不同符号、间距 > 相邻容差） | `["file"]` | `["block","symbol"]` | `[]` | 实测：不同函数的改动 git **自动合并成功**（exit 0）→ 区块级不得报；题面要求"文件级冲突，符号级不报同一符号" |
| 2 | `same_symbol_diff_lines` | 两会话改**同一函数** `f()` 的首段与尾段（相隔 ≥4 行） | `["file","symbol"]` | `["block"]` | `["f"]` | 实测：同函数内相隔 3~5 行 git **仍自动合并**（exit 0）→ **这正是符号级的价值窗口**：git 说没问题、我们报同一符号 |
| 3 | `whole_file_overwrite` | 一侧 `Write` 整文件覆盖、另一侧局部 `Edit` 同一区域 | `["file","block","symbol"]` | `[]` | `["f"]` | 实测：整文件覆盖 vs 局部 Edit → git exit 1（必冲突）→ 区块级必须报；题面要求"文件级 + 符号级（被覆盖符号）" |
| 4 | `subagent_derived` | 同一 parent 派生的两个 subagent 改同一文件同一函数 | `[]` | `["file","block","symbol"]` | `[]` | 题面：默认不报跨 agent 冲突；必须标注 `derived_from` |
| 5 | `negative_no_overlap` | 两会话改完全不重叠的文件 | `[]` | `["file","block","symbol"]` | `[]` | 防误报：空检出 |
| 6a | `threshold_exact` | 同文件、两侧改动落在**不同符号**且改动区间间距 **== `symbol.adjacent_tolerance`** | `["file","symbol"]` | `["block"]` | `["f","g"]` | 验"达到阈值即命中"（`≥` 语义） |
| 6b | `threshold_near_miss` | 同上但间距 **== `adjacent_tolerance` + 1** | `["file"]` | `["block","symbol"]` | `[]` | 验"不到不命中"——没有这条，阈值边界语义从未被测过 |

**真值同时登记构造参数**（`geometry`：两侧改动行区间与间距），使期望值可由输入**独立复算**：
把检测引擎注释掉，真值仍算得出来（判别 = "把引擎实现注释掉，真值还能算出来吗？"）。

> 场景 6 拆成 `6a`/`6b` 两条**成对**样本是硬要求：只测"该命中"的用例，阈值写错永远不会红。

## 五、覆盖度门槛（写在 `bench/manifest.json`）

```json
{"generator_version":"<随包常量，不手写第二份>",
 "coverage":{"min_count_by_type":{"same_file_diff_symbol":1,"same_symbol_diff_lines":1,
                                  "whole_file_overwrite":1,"subagent_derived":1,
                                  "negative_no_overlap":1,"threshold_adjacent":1}},
 "scenarios":[{"id":"…","truth_sha256":"…","cases":[{"case_id":"…","truth_sha256":"…"}]}]}
```

三条纪律：

1. **覆盖率是"集合覆盖"不是"条数达标"**：每类最低条数达标且 `missing_types` 为空才算过；缺类**不得**用别的类凑。
2. **覆盖声明双登记**：`规则/场景总数` 与 `采样数` 分开写，并显式声明"抽样覆盖非穷举"，防"各有件"被读成"全穷举"。
3. **计数口径先声明**（K12）：这里的计数是**用例条目数**（一个 case 一条），不是"命中记录数"。

## 六、生成与冻结纪律

| 纪律 | 落地 |
|---|---|
| 确定性 RNG | 自研 splitmix64 风格；**禁 stdlib `random`**（不承诺跨版本序列一致） |
| 禁系统时钟 | 产物无时间戳字段；会话时间戳为固定基准 + 确定偏移 |
| 禁 set 迭代序 | 遍历前先排序成 list |
| git 提交稳定 | 固定 `GIT_AUTHOR_DATE` / `GIT_COMMITTER_DATE` / 作者名，保提交 sha 可复算 |
| 容器字节冻结 | 若产出 zip/归档：`ZIP_STORED` + `create_system=0` + 固定 `date_time` |
| 两层 `--check` | ① 断言**冻结产物自身形态**（真值无 `observed_*`、三态计数自洽）；② **重跑生成器到临时目录 → 与冻结产物逐字节比对**。只做①会在生成器被改坏时照常绿（假门头号来源） |
| 台账 | `manifest.json` 的值（含 sha256）是**生成物**，由脚本复算，**禁手改**；改生成器 → 整目录重生成并同步提交 |
| 生成物不登记环境依赖事实 | 登记的值必须是**输入的函数**（如"声明了几条用例"），不是"目录里实际有几个文件"（后者在干净 clone 上算出的值不同 → `--check` 必红） |
| 写盘单点 | 全部经 `serialize.write_atomic`（K2）；生成器与生产侧各一份独立实现，一致性靠逐字节测试（K10）。**M5**：`bench/last_run.json` 也走这条；它是**运行产物**而非生成物，`RUNTIME_PRODUCTS` 单元素集合放行它，并有双向测试（放行它 / 换名必红） |

**命令形态**

```bash
# 重建整目录（改体例/生成器后必须走这条；生成器会先清掉自己的产物面再落盘）
py -X utf8 -m agent_conflict_radar.bench.gen --out bench

# 两层自检（CI 与每棒收尾必跑）
py -X utf8 -m agent_conflict_radar.bench.gen --check

# 把某条场景物化成真 git 仓库 + 真会话日志（M2/M3 与人工复核用）
py -X utf8 -m agent_conflict_radar.bench.gen --materialize same_symbol_diff_lines --dest out/scene

# 跑矩阵对账（M5）
py -X utf8 -m agent_conflict_radar bench
```

**M1 落地的账**（对外可核验的实物）：`bench/manifest.json` 的 `coverage.min_count_by_type` 就是 §五 的门槛值
（每类各 1，六类齐全、`missing_types` 为空）；`threshold_adjacent` 恰好两条，且卡在容差两侧
（`threshold_exact` 的间距 = `config:symbol.adjacent_tolerance`，`threshold_near_miss` = 该值 + 1）——
**这两条关系不在真值里写死数值**，而是以符号引用指向 config，由 `--check` 现场求值。

## 七、真实数据的使用边界（只读演示）

| 项 | 约定 |
|---|---|
| 读取 | 只读用户本机会话目录（默认探测常见位置，可显式传 `--claude-root` / `--codex-root`） |

## 九、M2 意图矩阵（与 M1 的冲突矩阵分开冻结）

**为什么单独一棵树**：M1 的冲突真值判据是"每条场景恰好两个改动侧 + 符号区间落在基线内"，
而 M2 的意图真值要覆盖 `MultiEdit`（本机 0 次出现的形态）与"缺 `file_path`"这类**没有文件**的写操作——
把两者塞进同一棵树，`--check` 的那些"必须有两条几何"的判据就得被迫放宽。**改松门禁换一次性便利，是这笔账里最不该做的选择。**

| 路径 | 内容 |
|---|---|
| `bench/intents/manifest.json` | 场景清单 + `coverage.min_count_by_type`（`intent_precision` ≥ 2、`non_python_approximate` ≥ 1）+ `missing_types` + 每条真值的 sha256 |
| `bench/intents/<id>/repo/` | 基线源码 = M1 基线 + `src/dup.py`（歧义锚点）+ `docs/notes.md`（非 Python） |
| `bench/intents/<id>/sessions/` | 合成会话日志（`{{REPO_ROOT}}` 占位符） |
| `bench/intents/<id>/truth.json` | `entries_expected`（有路径的条目，逐 `(path, session)`）+ `unknown_expected`（未定位写操作，**写操作条数**）+ `counts_expected` + `geometry`（基线行数 / 逐 op 的锚点与命中次数 / 磁盘脏改动） |

**八条意图场景**（每条对应三分法的一条分支或一条降级纪律）：

| 场景 id | 覆盖什么 |
|---|---|
| `intent_edit_exact` | 唯一锚点 → `exact`；同一份日志里的 `Read`（非写工具）**不得**产出条目 |
| `intent_replace_all_coarse` | `replace_all=True` → `coarse` 且**无区间** |
| `intent_ambiguous_anchor_coarse` | 锚点两处命中 → `coarse` + 点名 `anchor_ambiguous#2`（**不挑第一个**） |
| `intent_multi_edit_unknown` | `MultiEdit` → `unknown` + 计注记；同会话另一条 `Edit` 仍精确 |
| `intent_codex_exec_patch` | R2 第二形态（`exec` 同形变体）→ 认出；不含 patch 标记的 `exec`（反例）→ 不算写操作 |
| `intent_write_and_non_python` | 整文件 `Write` 的有效改动区间；`docs/notes.md` → `approximate=True`（R4） |
| `intent_multi_write_merge` | **同会话同文件两次写入** → 合并成一条条目（区间并集 + `last_write_ts` 取组内最大），而 `write_ops == 2`（两个口径分开登记） |
| `intent_disk_wins` | `git diff` 与 `git diff --cached` **两条通路**（一条 staged + 一条 unstaged）；磁盘与会话不一致 → 以磁盘为准 + 点名 `disk_and_session_disagree` |

**真值纪律沿用 §六**（生成器与真值同步产出、禁手补、`--check` 两层、零绝对路径、提交 sha 可复算）；
**M2 追加两条**：

1. **写操作条数与条目数分开登记**（K12）：`unknown_write_ops` 是**写操作条数**（一个会话的多次未定位写操作合并成一条
   unknown 条目，故它 ≥ `unknown`），`counts_expected.entries` 是**条目数**；`--check` 与测试各断言一次。
2. **三分法是集合划分**：`exact + coarse + unknown == entries` 写成 `--check` 的恒等式断言
   （`_check_intent_payload`），不是"看着差不多"。

**命令形态补充**：

```bash
# 物化某条意图场景（真 git 仓库 + 真会话日志 + 未提交改动）
py -X utf8 -m agent_conflict_radar.bench.gen --materialize-intent intent_disk_wins --dest out/intent-scene
```

**`--check` 现场复核的账（M2）**：① 每条意图真值的 sha256 与台账一致；② 冻结文本重生成逐字节一致；
③ 意图场景的提交 sha 可复算；④ **`dirty` 声明真的落成了未提交改动**——`staged` 的出现在
`git diff --cached --name-only` 里、`unstaged` 的出现在 `git diff --name-only` 里（`_check_intent_worktree`）。
第 ④ 条是必需的：真值里的区间期望建立在"磁盘上确实有这么一块改动"这一事实上，只比对冻结文本**永远发现不了**
"物化没把改动写进去"。

## 十、M3 的检出对账（**复用 M1 的冲突矩阵，不另造夹具**）

M3 不给矩阵加任何新场景：`bench/scenarios/` 的七条场景本来就是为"两条分支 + 会话"准备的
（每条都冻结了 `git_expected_merge_exit`，并由 `--check` 现场真跑 merge-tree 复核）。M3 做的是
**把引擎接到这些真值上，按集合精确匹配对账**：

| 真值字段 | 在 M3 里怎么用 |
|---|---|
| `levels_expected` / `levels_forbidden` | 检出记录的 `levels` **集合**必须等于前者、与后者不交（多报、漏报均失败） |
| `symbols_expected` / `symbols_forbidden` | 检出记录的 `symbols` **集合**同上 |
| `objects_expected` / `objects_forbidden` | 按 `(path, symbol)` 逐对象核对；`symbol: null` 表示"该条只到文件级" |
| `geometry.sides[].changed` | 报出的 `line_ranges` 必须落在这些**构造区间**里（可人工复算） |
| `git_expected_merge_exit` | 区块级只在这条为 1 时命中（`--check` 现场真跑复核，M1 起） |

**命令与入口**：`py -X utf8 -m agent_conflict_radar detect --repo <物化出的 repo> --claude-root … --codex-root … --now …`；
物化入口 `… bench.gen --materialize <id> --dest <dir>`（M1 起）。

**M3 另加的四类合成用例（不进冻结树）**：三态（`degraded` / `approximate` / `unsupported_format`）与
"两个 worktree 共享仓库"这四种形态在七条冻结场景里**没有落点**（它们都是 Python 文件 + 两条正常分支），
硬塞进去就得改真值与台账。处置：在 `tests/test_detect_parse.py` 里**手造最小夹具**
（真 git 仓库 + 真会话日志，几十行），**不动冻结产物**。这些用例与矩阵对账**互不替代**：
矩阵守"检出的集合对不对"，它们守"判不出来时说什么"。

## 十、M5 评分（`radar bench`）的口径

**一句话**：把每一条场景**物化**成真 git 仓库 + 真会话日志，跑 `scan → intent → detect` 完整链路，
再与 `truth.json` 的**期望集合**做集合精确匹配。

| 环节 | 判据 | 失败形态 |
|---|---|---|
| 会话归集（M1） | `scan.sessions` 集合 == 真值 `sessions` | 漏一个/多一个都失败 |
| 改动意图（M2） | `(path, session)` 集合 == 真值 `geometry.sides` 的 `(path, session)` | 同上 |
| 检出集合（M3） | `levels` / `symbols` / `objects` 分别集合精确匹配 | 多报（`extra`）/ 漏报（`missing`）**均计失败** |
| 反向样例 | `objects_forbidden` / `levels_forbidden` / `symbols_forbidden` 命中即失败 | 适用域写错会在这里红 |
| 退出码口径 | 真值有 `levels_expected` → 期望 1，否则 0 | 与 `detect` 的判定口径对齐 |
| 意图条目 | `(path, session_id, precision)` 展开后集合匹配 + `counts_expected` 逐项相等 + `paths_forbidden` | coarse/unknown 分支各自有样本 |
| 台账与覆盖度 | 真值 sha256 == manifest 台账；`count_by_type` == 实算；`min_count_by_type` 全达标；`missing_types` 为空 | **在消费侧再验一遍**，不只信生成器 |

**覆盖度按整棵矩阵算**（不受 `--only` 影响）：覆盖度是矩阵的属性，不是"这次跑了哪几条"的属性。
用过滤后的子集算，会让 `--only` 一次就报"缺类"。

**`--only` 的两种用法错误**（都退 2）：未知场景 id、过滤后为空。
"零条通过"绝不能被读成"基准通过"。

**确定性**：参考时刻是模块常量 `2026-01-01T00:10:00Z`（合成会话的固定基准 + 固定偏移），
**不读系统时钟**——否则同一天不同时刻跑会得到不同判定。

**产物**：`last_run.json`（默认落矩阵目录，`--out-dir` 可改），冻结序列化契约（K2），
**不含本机路径 / 时间戳 / 用户名**（K17，失败信息里的临时路径替换成 `{{WORK}}` / `{{BENCH}}`）。
